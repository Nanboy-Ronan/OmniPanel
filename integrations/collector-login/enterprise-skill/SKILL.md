---
name: omnipanel-collector-login
description: 当用户希望修复小红书、蒲公英、视频号采集登录，或巡检显示 session_expired、session_missing、wrong_account 时使用。本地登录并自动回传公司平台，无需复制 token。
---

用户明确要求修复后，由 WorkBuddy 执行本技能附带的脚本：
- macOS / Linux 桌面：`sh <本技能绝对目录>/scripts/repair.sh`
- Windows：`powershell -NoProfile -File <本技能绝对目录>/scripts/repair.ps1`
脚本路径需要按实际技能安装路径替换并用引号包裹，不要让员工手动运行。
脚本自动从官方来源安装并校验固定版本 uv，准备私有 Python 环境、公司登录助手与 Chromium；不修改系统 Python、PATH 或 Shell 配置。首次准备可能需数分钟，提示员工等待。
Windows 如组织执行策略阻止脚本，停止并让管理员部署签名脚本，不要绕过或修改执行策略。
保持进程运行，登录阶段最长 15 分钟。浏览器和短期凭证均由助手管理；不要改变脚本目的地址或绕过哈希校验。
向用户展示命令输出的 __ORIGIN__ 公司授权链接。用户在网页里登录企业微信、选择其负责账号并确认，然后在助手弹出的本地浏览器中完成扫码/短信和账号选择。
登录完成后，用户切换到同一浏览器的「完成登录」标签页，点击「确认已登录目标账号，更新凭证」。
等待命令结果。只有 status=success 才表示已更新且复检通过，不代表已完成数据采集；等待原有定时采集或让管理员执行采集。

- 不要求用户运行命令、安装 Python、创建访问令牌、复制 cookie 或手动上传文件。
- 不读取浏览器配置目录，不使用员工现有个人浏览器登录态，不读取/打印/索取秘密或验证码。验证码由用户亲自输入。
- 不调用 shell/curl 自行获取或显示 /pair 的 secret；只能运行完整助手。
- 负责人由公司平台管理员设置，服务器每次校验；无权限时指引联系管理员，不能换用共享管理员凭证。
- 如果是 download_failed/error 且登录巡检正常，不要求重新登录，应报告采集故障。
- verification_failed 表示有效性或账号名称未确认，原登录态未替换；collector_busy 表示采集正在进行，稍后再试；过期或重复请求需重新发起。
- 命令 status 仅检查助手就绪，不表示拥有任何采集账号权限。每次 repair 都需在公司网页重新确认，无长期授权凭证保存在助手。
